4. How a turn gets sorted

Left: the tool every main thread gets, Claude or Codex. Sub-agents don't get it, and their asks are never shown: their last message is for the agent that started them, not you.

Right: what decides the row, in order. No model call anywhere.

The projects librarian reads the same open asks for a project's "what's blocked", instead of guessing, in the same pass at the end of a turn.

The tool

end_turn({
  needs: "you" | "nothing",
  asks?: [{
    action: string,  // one concrete thing to do
    where?:  string, // app, site, file or person
    reply?:  string, // the words to send back
  }],
})

// e.g.
end_turn({
  needs: "you",
  asks: [
    { action: "Paste your OpenRouter key
        into Settings and turn on titles",
      where: "Threadbare › Settings › Models",
      reply: "done" },
    { action: "Say whether a $1 daily budget
        is right, or give me a number" },
  ],
})

What the runner tells the agent

Call end_turn as the last thing in every turn.
needs "nothing" when the work is finished and
nothing waits on Mike; otherwise list each thing
he has to do, one action per ask.

When a turn finishes

  1. Waiting on an approval or a question
    Needs you, as now.
  2. You marked it unread
    Needs you, as now.
  3. It called end_turn
    Use what it said.
  4. It forgot, but ended with "What I need from you"
    Parse that instead: the last bold line with that heading near the end, then its numbered or bulleted items. "Nothing needed from you" under it means done. Completed turns only.
  5. Neither
    Today's rule: a finished turn you haven't read needs you.

Notifications

Only for "needs you". The banner reads "Paste your OpenRouter key into Settings and turn on titles" under the thread's title, rather than the last line of the reply.
